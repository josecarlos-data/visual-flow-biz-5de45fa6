- Password changes go through the cambiar-password edge function acting as the user (updateUser), never the admin API, so server password checks (HIBP) apply and only that function clears profiles.debe_cambiar_password.
- User state (profiles.estado) is enforced in the database via is_approved and is_admin; state changes go only through the admin_cambiar_estado / admin_dar_baja RPCs so sessions and audit stay consistent.
- Second factor (TOTP) is enforced in the database: is_approved/is_admin require public.sesion_cumple_2fa() when evaluating the caller; resetting factors goes only through the admin-segundo-factor function. Why: the client gate alone can be bypassed.
- User/role/dashboard-access changes are audited by the auditar_cambio_usuario trigger (also for service-role writes); session max age is enforced in verificar_sesion from the oldest amr timestamp. Why: changes and expiry must hold regardless of which client or tool acts.
- Landing route after login comes from src/lib/destinoInicio.ts (Ventas if assigned, else first permitted dashboard); ProtectedRoute redirects "/" silently. Why: roles without Ventas must not log a false acceso_denegado.
- Ofertas/Comunicaciones are gated by app_settings.ofertas_activo: DB RPCs raise «Ofertas desactivado», a trigger syncs dashboards.is_active, the client hides entry points via useOfertasActivo. Why: one switch must disable the section server-side, not just hide it.
- Objetivos v2 live in objetivos_v2/objetivo_asignaciones/objetivo_clientes with a tipos_objetivo catalog (visible/disponible); progress is computed only server-side by objetivos_v2_* RPCs over objetivo_filas, and each objective stores its own attribution and comparison criteria. Why: new objective types must plug in without reworking, and migrated 2026 figures must not change.
- Reviewer corrections of block data go only through editar_bloque_revision (version check, template fields, validation untouched); field changes on visita_bloques are audited before→after by trg_visita_bloques_auditar_campos, skipping admin writes on non-app visits. Why: corrections must be traceable without flooding Auditoría with import batches.
- NuevaVisita: dictating only transcribes; extraction runs on explicit «Crear/Actualizar bloques» and replaces only blocks with origen "voz"; the AI never changes resultado; one localStorage draft per user (src/lib/borradorVisita.ts) cleared only on save, discard or manual logout. Why: saved text and blocks must match and work must survive reloads/expulsions.
- After registration a visit is closed to its author: visitas UPDATE excludes the owner, DELETE is admin-only, block writes go through puede_revisar_bloque (others' visits) or puede_crear_bloque_propio (inside registrar_visita, or while visita_alta_directa_bloqueada is false); authors change data only via completar_bloque. Why: field data must not change after the fact except through audited RPCs.
